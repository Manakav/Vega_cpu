# Vega SoC 剩余 Part 清单（从 CPU 到可上板 SoC）

最后更新：2026-04-09

---

## 1. 当前状态快照

- CPU 内核：6 级双发射流水线已可运行，RTL 仿真可通过。
- ICache/DCache：模块级原型与单测可跑，但尚未完成系统级集成。
- Vivado：综合可完成，实现阶段失败。
- FPGA 上板：未形成可下载比特流的 SoC 形态。

说明：当前工程仍偏“CPU 核 + 外部测试内存接口”，距离完整 SoC 还缺少板级封装、片上存储子系统、约束与实现闭环。

---

## 2. 最高优先级（P0，阻塞上板）

### P0-1 顶层封装与 I/O 收敛
目标：将 CPU 顶层改为 SoC 顶层，避免把大总线直接暴露为 FPGA 引脚。

待完成：
- 新建 board top（例如 vega_soc_top）
- 仅保留必要板级口：clk、rst、uart_tx/rx、可选 led/gpio
- CPU 指令口与数据口接入片上存储/总线，不再直连外部大量 I/O

验收标准：
- 设计总 I/O 数显著低于器件可用引脚数
- Place 不再出现 I/O overutilization

### P0-2 约束文件（XDC）补齐
目标：满足实现与 bitstream 生成的基础约束要求。

待完成：
- 时钟约束（create_clock）
- 复位、UART、GPIO 等管脚 LOC
- 所有顶层口 IOSTANDARD
- 必要的 false_path / clock_groups（如存在异步域）

验收标准：
- 消除 UCIO-1、NSTD-1 类关键 DRC
- 可进入 write_bitstream 阶段

### P0-3 组合环修复（LUTLP-1）
目标：消除 IF 路径组合环，恢复可靠时序分析。

待完成：
- 定位并打断 IF 级组合反馈
- 必要时引入寄存器或重构组合逻辑路径
- 不建议用放宽 DRC 的方式长期掩盖

验收标准：
- DRC 不再报 LUTLP-1
- timing report 具备可解释性

---

## 3. 上板最小可用 SoC（P1，Bring-up 里程碑）

### P1-1 片上存储子系统（最小版）
目标：支持当前启动程序运行。

待完成：
- 指令存储：ROM/BRAM（可由 hex 初始化）
- 数据存储：RAM/BRAM（至少满足栈与 .data/.bss）
- 地址映射：划分 ROM、RAM、UART MMIO 空间

验收标准：
- 可从复位地址正常取指
- C 启动流程可走通（含栈）
- 串口可输出可观测信息

### P1-2 UART 外设与基础 SoC 总线胶水
目标：形成最小可观测系统。

待完成：
- UART Lite 或自研 UART Tx/Rx
- CPU 数据访问到 UART MMIO 的译码与应答
- 基础总线仲裁（至少单主设备直连版）

验收标准：
- 上板后能输出启动 Banner 或心跳日志
- 读写 UART 寄存器稳定

### P1-3 复位与时钟基础设施
目标：保证板上启动稳定性。

待完成：
- 时钟源接入（板卡时钟 + PLL/MMCM 视需求）
- 复位同步器
- 上电复位时序确认

验收标准：
- 多次上电复位行为一致
- 无随机卡死、无亚稳态明显症状

---

## 4. 功能完备 SoC（P2，性能与工程化）

### P2-1 Cache 系统级集成
目标：将 ICache/DCache 从“模块原型”升级为“SoC 可用”。

待完成：
- 接入 CPU IF/MEM 主路径
- 打通 miss/stall/replay 时序
- 修正地址切分、行偏移、写掩码等细节
- 完成 dirty 回写与替换策略闭环（DCache）

验收标准：
- 系统级测试在 cache 开启下稳定通过
- 关键访存场景（命中、缺失、写回）可回归

### P2-2 中断与 CSR 系统联调
目标：补全机器态软件运行能力。

待完成：
- 外部/定时器/软件中断到 CSR 路径联通
- trap 入口、返回流程验证

验收标准：
- 中断触发、响应、返回可重复通过

### P2-3 调试与可观测性
目标：提升 bring-up 与定位效率。

待完成：
- 关键性能计数器（周期、退休、cache miss、分支命中）
- 可选调试接口（JTAG/简化调试口/ILA 探针）

验收标准：
- 问题可在板上快速定位
- 性能指标可量化

### P2-4 软件与基准
目标：形成 SoC 级交付能力。

待完成：
- 裸机启动包整理（链接脚本、启动文件、驱动）
- 基础功能测试集
- CoreMark/Dhrystone 跑通

验收标准：
- 基准可稳定复现
- 性能结果可对比

---

## 5. 验证与交付门槛

### 5.1 仿真门槛
- RTL 回归通过（模块级 + 系统级）
- SoC 启动程序仿真通过（含串口输出检查）

### 5.2 实现门槛
- synth/impl 全流程通过
- 关键 DRC 为 0（至少无阻塞 bitstream 的项）
- 时序满足目标频率（WNS >= 0）

### 5.3 上板门槛
- 可下载并稳定启动
- 串口输出与仿真一致
- 长时间运行稳定（建议最少 1~8 小时稳定性测试）

---

## 6. 推荐执行顺序（两周到四周计划）

第 1 阶段（先可上板）：
1. 顶层封装与 I/O 收敛
2. XDC 约束补齐
3. 修复组合环
4. 最小 ROM/RAM + UART 跑通

第 2 阶段（再做完整 SoC）：
1. Cache 系统级集成
2. 中断/CSR 联调
3. 基准测试与性能优化
4. 文档与交付物整理

---

## 7. 交付物清单（建议）

- RTL：soc top、存储子系统、外设、约束
- 脚本：一键仿真、一键综合实现、一键生成 bit
- 报告：资源、时序、功耗、基准、已知问题
- 文档：地址映射、寄存器手册、上板指南、回归说明

---

## 8. 一句话结论

当前项目已完成“CPU 可仿真运行”的核心阶段；距离“可上板 SoC”还需优先完成三件事：
- 顶层 SoC 化（I/O 收敛）
- 约束完整化（XDC）
- 实现可闭环（修复组合环并跑通 bitstream）

完成后再推进 cache 系统级集成与性能化工作。
