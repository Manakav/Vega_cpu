# 功能真实性验证指南

## 目标

验证 CPU 不仅能通过语法/冒烟仿真，还能真实执行指令并产生可检查的架构状态结果。

## 当前实现内容

顶层测试文件 `test/riscv_cpu_tb_dual.v` 已加入以下真实性校验：

1. 程序加载到复位取指地址对应窗口
- CPU 复位后 PC=0x1000，对应 `imem[1024]`。
- 测试程序已写入 `imem[RESET_PC_WORD_IDX + n]`，避免“程序未执行但仿真通过”。

2. 写回退休计数
- 按 WB 写使能统计退休数：
  - `u_dut.wb_we1`
  - `u_dut.wb_we2`
- 若 `instr_count == 0`，判定为真实性失败。

3. 终态架构状态断言
- 期望：
  - `x1 == 1`
  - `x2 == 3`
  - `x6 == 9`
- 通过层级访问寄存器堆：`u_dut.u_register_file.rf[idx]`。

## 测试程序

从复位地址开始执行如下指令：

1. `ADDI x1, x0, 1`
2. `ADDI x2, x0, 2`
3. `ADD  x2, x1, x2`
4. `ADDI x6, x0, 9`
5. `NOP`
6. `NOP`

## 运行方法

### 方式 1：快速 RTL 仿真

```bash
bash test/run_rtl_sim.sh
```

### 方式 2：完整验证套件

```bash
bash test/run_verification_suite.sh
```

## 通过判定标准

满足以下全部条件判定“功能真实性通过”：

1. 编译成功（无语法错误）。
2. 仿真结束时 `error_count == 0`。
3. `instr_count > 0`（观察到真实写回退休）。
4. 寄存器终值匹配：`x1=1`、`x2=3`、`x6=9`。

## 常见失败定位

1. `instr_count == 0`
- 重点检查测试程序是否写入复位 PC 对应地址（0x1000 -> `imem[1024]`）。

2. 寄存器值不匹配
- 检查 II 发射阻塞与前递路径是否影响依赖指令。
- 检查 WB 写使能与目的寄存器号是否正确。

3. 仿真通过但真实性失败
- 说明仅满足“能运行”，不满足“执行结果可信”。
- 需保留终态断言，不建议仅以 `error_count` 或“无报错”作为通过条件。
